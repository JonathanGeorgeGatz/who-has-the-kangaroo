Prompt 1 — The spec
GOAL
One screen that always knows which animals and which equipment are signed out,
with whom, and for how long.

DATA
Animals (name, species, class)
Equipment (item, category)
People (staff roster)
One log row per item per outing.

RULES
1. Two people can never take the same animal.
2. The form shows only what is actually available.
3. Anyone can return a colleague's animal.

Build this on Google Sheets with Apps Script. No external services, no database,
no paid APIs — it has to run inside one ordinary Google account. Give me a
setup() function that creates the whole spreadsheet structure, formatted, with
sample data I can delete.

Never ask AI to "build software." Give it a spec: Goal, Data, Rules. The Rules section is the part that saves you later. Swap the nouns for yours.

Prompt 2 — The form that thinks
Build the check-out page as a web app, not a Google Form.

IT MUST:
- rebuild the item list on every scan from the log — anything already out must
  not appear at all
- remember the person on that device and pre-select their name next time
  (localStorage is fine; add a "Not you?" switch)
- let one submission carry several animals and several pieces of equipment at
  once, each getting its own log row so they can come back separately
- take four seconds to use, not forty — this is being used by volunteers
  holding a live animal, one-handed, outdoors

Serve it from the same Apps Script project. It opens from a QR code.

This is what makes it a web app instead of a Google Form. A form shows everybody the same list forever.

Prompt 3 — The follow-up that fixed the bug
Two people can scan at the same second and both get the stale list. Add a lock:

- take a script lock before writing anything
- re-read what is actually out, inside the lock
- if any requested animal is now taken, write nothing and return which ones
  went, with a message telling the user the list refreshed
- always release the lock in a finally block

Then prove it: write a test that fires two submissions for the same animal in
the same second, and show me that exactly one succeeds.

The first version worked, and it let two people check out the same animal in the same second. This is the prompt that added the lock.

Prompt 4 — The wall board
Add a wall dashboard page to the same web app, for an old iPad mounted by the
door.

- shows everything currently out: item, category, who has it, how long
- elapsed time ticks every second and the page refreshes itself
- colour by age: green under 6 hours, amber from 6, red from 8
- big enough to read from across a room; no interaction required

Nobody should have to interpret it. If there is red on the board, something is
still out that shouldn't be.

The screen by the door. Nobody should have to interpret it.

How to check what you get back

Don't trust it because it ran. Try to break it:

  1. Submit the same item twice, at the same moment, from two browsers.
  2. Add a row with a missing field and submit.
  3. Return an item that somebody else checked out.
  4. Check something out, check it in a minute later, and confirm the duration and status both land correctly.
  5. Paste in a hundred rows and make sure the dashboard still adds up.

If any of those does something surprising, that's your next prompt.
